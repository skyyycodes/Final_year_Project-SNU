\chapter{Problem Identification}
\label{Problem_Identification}

\section{Problem Statement}

Despite substantial progress in information hiding, reliable multi-watermark, multi-modal embedding remains difficult because existing systems are non-uniform across carriers, are tightly coupled to a single embedding location, and are silent in the presence of overwrite collisions. Single-modality LSB pipelines can model perceptual transparency very well, but they remain reactive to the way the cover is used and therefore lag the multi-recipient, multi-medium distribution scenario that motivates the present work.

Concretely, consider a digital-content owner (for example, a photographer, a recording artist, a technical-document author or a film studio) who routinely distributes media files to multiple downstream recipients such as clients, distributors and reviewers. The owner needs a single tool that can: (1)~stamp every outgoing copy with a recipient-specific watermark that survives ordinary handling but cannot be casually erased; (2)~embed several such watermarks into the same master file so that one shared master can be customized per recipient without re-rendering the cover; (3)~operate uniformly across the four media types that constitute most modern digital content (still images, audio recordings, written documents and video clips); (4)~allow the owner to recover any individual watermark, given only the cover file and the password used at embedding time; and (5)~time-stamp every embedding so that disputes about \emph{when} a particular copy was issued can be settled from the recovered payload alone. No off-the-shelf academic system simultaneously satisfies all five requirements.

\section{Formal Statement of the Problem}

Let $C$ denote a cover file drawn from one of the supported carrier types (a $256 \times 256$ BMP image, a WAV audio file, a plain-text file or a video container). Let $\mathcal{W} = \{w_1, w_2, \ldots, w_n\}$ denote a set of $n$ ASCII watermarks with $|w_i| \le 16$, and let $\mathcal{P} = \{p_1, p_2, \ldots, p_n\}$ denote a corresponding set of pairwise-distinct passwords. The embedding operation
\[
    E : (C, w_i, p_i) \longmapsto C'_i
\]
must produce a stego-cover $C'_i$ that is perceptually indistinguishable from $C$, and the corresponding extraction operation
\[
    D : (C'_i, p_i) \longmapsto (w_i, t_i),
\]
where $t_i$ is the embedding timestamp, must recover both the watermark and the timestamp exactly. When two passwords $p_i, p_j$ ($i \ne j$) are applied in sequence to the same cover, the system must either embed both watermarks without mutual interference or refuse the second embedding and report a collision.

\section{Research Gap to be Solved}

From Chapter~\ref{Literature_Survey}, the core unresolved gap is not the absence of powerful LSB algorithms, but the absence of a consistent, leakage-safe integration strategy for combining:

\begin{itemize}
    \item password-keyed, deterministic location selection,
    \item multi-watermark capacity inside a single cover,
    \item explicit collision detection before each embedding, and
    \item a unified payload format across image, audio, text and video.
\end{itemize}

Existing work often addresses one or two of these elements, but rarely all four in a reproducible, deployment-oriented pipeline backed by a single graphical front-end.

\section{Why Existing Methods Are Insufficient}

Current single-modality LSB systems underperform when the same cover must hold several recipient-specific marks, or when the same author must publish across image, audio, text, and video. Even more advanced transform-domain schemes still depend on separate preprocessing for each file type, weak alignment between payload format and cover format, and limited collision reporting. As a result, reported gains do not always transfer well to realistic multi-recipient workflows. A tool that embeds one robust watermark per image is not the same as a tool that embeds 256 password-keyed marks per image, refuses overwrites, and uses the same payload format for WAV or Markdown files.

\section{Research Objectives and Hypotheses}

\subsection*{Objectives}

\begin{enumerate}[label=\textbf{O\arabic*.}]
    \item Build a multi-modal information-hiding workflow that separates GUI logic from per-modality embedding logic and exposes all four carriers behind a single user interface.
    \item Integrate a password-keyed, MD5-derived location-selection mechanism into the image module, so that up to 256 watermarks may coexist in the same cover.
    \item Provide an explicit, leakage-safe row-occupation marker that detects collisions before any embedding writes back to the cover.
    \item Define a single self-delimited timestamped payload format reused by all four modalities so that a single parser recovers the watermark and timestamp regardless of carrier.
\end{enumerate}

\subsection*{Hypotheses}

\begin{itemize}
    \item \textbf{H1}: A row-based LSB scheme in which the row index is derived from the first 12 bytes of an MD5 digest of the user's password admits up to 256 password-keyed, mutually non-interfering watermarks per $256 \times 256$ cover, with the row choice approximately uniform over $\{0, \ldots, 255\}$.
    \item \textbf{H2}: A single sentinel character `\$' embedded at column~0 of every occupied row reliably blocks overwrite collisions on a second embedding under a colliding password, without any additional side channel and at $O(1)$ cost per attempt.
    \item \textbf{H3}: A self-delimited timestamped payload of the form $\texttt{*}\,w\,\texttt{\#}\,t\,\texttt{\#@}$ enables a single extraction parser to recover both the watermark and the timestamp from any of the four supported modalities, with no per-modality parser specialization.
\end{itemize}

\section{Threat Model and Assumptions}

The proposed system is designed under the following threat model.

\begin{description}
    \item[Adversary capability.] The adversary may obtain the stego-cover $C'_i$ but does not know any of the embedding passwords $p_i$. The adversary may attempt to read the file with a hex editor, run statistical steganalysis on it or apply standard signal-processing transforms (for example, lossless re-saving, format conversion, or random pixel inspection).
    \item[Adversary limitations.] The adversary cannot mount a chosen-password attack on the MD5 digest, cannot brute-force the password space (assumed to contain at least $\sim 10^{12}$ candidates), and does not have access to the original cover $C$ for differential analysis.
    \item[Channel.] The cover is assumed to be transmitted through a \emph{lossless} channel. Lossy re-compression of an image (for example, conversion to JPEG) or of audio (for example, conversion to MP3) is outside the scope of the present system. For video, the system itself enforces a lossless re-encoding using FFV1 to keep the LSBs intact.
    \item[Trust.] The owner of the embedding password is trusted; the embedding tool itself is assumed to run on a non-compromised machine.
\end{description}

\section{Expected Challenges}

\begin{itemize}
    \item \textbf{Location uniformity}: deriving a row index $r$ and a column index $c$ that are jointly uniform over $\{0, \ldots, 255\}^2$ from a variable-length user password without leaking either index to an attacker who observes the cover.
    \item \textbf{Collision sensitivity}: making the row-occupation marker cheap to read but reliable enough to refuse overwrites under realistic password-collision rates.
    \item \textbf{Modality consistency}: keeping the same payload format across four very different carriers (image pixels, audio samples, text bytes, video frames) without inflating the per-modality logic.
    \item \textbf{Evaluation realism}: reporting both perceptual quality (PSNR, audible/visual inspection) and run-time on commodity hardware, rather than only one of the two.
\end{itemize}

\section{Identified Sub-Problems}

The high-level problem decomposes into the following five sub-problems, each of which is addressed in the proposed methodology of Chapter~\ref{Proposed_Methodology}.

\begin{enumerate}[label=\textbf{SP\arabic*.}]
    \item \textbf{Password-to-location mapping.} Design a deterministic, uniformly distributed mapping from a variable-length user password to a $(\text{row}, \text{column})$ pair in $\{0, \ldots, 255\}^2$.
    \item \textbf{Per-pixel character encoding.} Design an encoding of an 8-bit ASCII character into the LSBs of a single 24-bit RGB pixel that minimizes per-channel perturbation and is reversible without side information.
    \item \textbf{Collision detection.} Design a row-occupation marker that allows the embedder to detect, before writing, whether the selected row is already occupied.
    \item \textbf{Self-delimited payload.} Design a payload format with explicit start, separator and end markers so that extraction can terminate without a length field.
    \item \textbf{Multi-modal reuse.} Design audio, text and video modules that share the same payload format and the same password input as the image module, so that the user experience is uniform across all four carriers.
\end{enumerate}
